## 1. 四项决议最终结论

### 决议①：sessions / adapters / 会话级 WS「统一事件协议」功能**保留**，强制鉴权**延后到 M4**

对应 M2 §7 **P1**。

- **结论**：`/api/v1/sessions/*`、`/api/v1/adapters/*`、会话级 WS `/ws/{session_id}` 这套「统一事件协议」功能**保留代码、不删除**，并**计划强制鉴权**。
- **本次范围（M2 收尾）明确不做**：
  - **不**开启会话级 WS 强制鉴权 —— `WS_SESSION_AUTH_REQUIRED` 维持默认 `false`。
  - **不**给 `sessions` / `adapters` 的 REST 端点加 `Bearer` 依赖（现有前端 sessions 功能尚未补传 token，贸然加会立即破坏）。
- **处置**：登记为明确的 **M4 待办**（见 §3），届时配合前端补传 token 一并落地。

### 决议②（本次主要代码改动）：cloud 模式下线 launcher 与 adapters 路由

对应 M2 §7 **P3**。

- **结论**：当 `DEPLOYMENT_MODE == "cloud"` 时，**不挂载** `launcher_router`（`/api/v1/launcher/*`）与 `adapters_router`（`/api/v1/adapters/*`）的 **HTTP 路由**；其余路由（auth / teams / projects / skill_forge / skill_store / sessions / ws）保持挂载。
- **local 模式维持现状**：全部路由照常挂载。
- **边界约束（重要）**：
  - 本次**仅**下线 launcher 与 adapters 两个路由。**未动** `skill_forge` 路由的挂载 —— 其 `browse/scan/migrate` 等本地能力的下沉属 **M3**，本次不处理。
  - cloud 下线的是 adapters 的 **HTTP 路由**（`/adapters/*`）；lifespan 内的 `AdapterRegistry.initialize_all(...)` **仍保留**（会话级 WS 的消息处理依赖适配器实例，且有 fallback）。**未因下线路由而移除 AdapterRegistry 初始化**。
  - `sessions_router` 在 cloud **保留挂载**。
- **实现**：`backend/app/main.py` 改为 `create_app()` 工厂，按 `settings.DEPLOYMENT_MODE` 条件挂载（详见 §4）。

### 决议③：JWT_SECRET 上线切换策略 = 一次性注入 + 全员重登

对应 M2 §7 **P4**、§3.2。

- **结论**：上线时**一次性注入** `JWT_SECRET`（生产强随机值）后发布，切换后旧 token 失效，**全员（含预设用户 DAIL / DAIL2）重新登录**即可；之后**非必要不轮换**（轮换 = 强制全员重登）。
- **性质**：**运维 / 上线动作，无需改代码**。仅写入上线清单（见 §2）。

### 决议④：设备配对令牌维持 M0「纯桌面主进程注入、云端不签发」

对应 M2 §6、§7 **P2**，M0 §5.2 / 分歧 D2。

- **结论**：**确认维持** M0 判定 —— 配对令牌由桌面主进程（Electron）生成并注入「本地代理进程」与「渲染层」，**云端不签发、不持有、不下发**。M2 已据此实现（仅落地 `core/security.py` 共享算法基线 `generate_pairing_token` / `verify_pairing_token` / `constant_time_compare`，未新增云端签发端点）。
- **性质**：**无需改动**，确认即可。M3 本地代理在 TS 侧等价实现该算法基线。

## 2. 上线清单（运维动作）

> cloud 形态发布前/发布时执行。除决议②已由代码按模式自动生效外，以下为运维需显式完成的动作。

- [ ] **JWT_SECRET 一次性注入 + 全员重登**（决议③）
  - 生成生产密钥：`backend\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"`
  - 在 cloud 环境注入 `JWT_SECRET=<上述值>` 后再发布；发布后通知全员（含预设用户 DAIL / DAIL2）**重新登录**。
  - 之后非必要不轮换（轮换即强制全员重登）。
  - 校验：cloud 启动日志**不应**出现「未设置 JWT_SECRET，cloud 模式正在使用公开的开发默认密钥」告警。
- [ ] **cloud 下线 launcher / adapters 路由**（决议②，代码已支持）
  - 设 `DEPLOYMENT_MODE=cloud`。
  - 校验：启动日志「已注册的 API 端点」中**不含** `/api/v1/launcher/*` 与 `/api/v1/adapters/*`；仍含 auth/projects/sessions/ws 等。
- [ ] **托管 MySQL TLS（如启用）**
  - 托管 MySQL 若强制 TLS，须设 `DB_SSL_ENABLED=true`（或提供 `DB_SSL_CA=<CA 路径>`），否则连接失败（参见 M1 §4、§11.5）。
  - 自签证书场景可设 `DB_SSL_VERIFY=false`（按需）。
- [ ] **（关联）Alembic schema 管控**（参见 M1 §7.4/§11.1，按运维节奏决定）
  - 现网 `cowork` 库由 `init_db` 建过表 → 启用 Alembic 时执行一次 `alembic stamp head`；并设 `DB_AUTO_CREATE=false` 避免双写 schema。

## 3. M4 待办登记

> 本次（M2 收尾）**不实现**，仅明确登记，避免遗漏。对应决议①。

- [ ] **会话级 WS / sessions / adapters 强制鉴权 + 前端补传 token**
  - 后端：开启 `WS_SESSION_AUTH_REQUIRED=true`，会话级 WS `/ws/{session_id}` 强制校验 token 且 `token_user_id == user_id`。
  - 后端：给 `sessions` REST（`/api/v1/sessions/*`，现默认 `user_id="demo-user"` 无鉴权）补加 `Depends(get_current_user_id)`。
  - 前端：`useWebSocket.ts` 在会话 WS URL 上补传 `token`（现仅传 `user_id`/`adapter_id`）；sessions REST 走 `apiClient`（已自动带 `Authorization: Bearer`），加鉴权对其透明。
  - 顺序：**前端补传 token 先行**，再后端置 `WS_SESSION_AUTH_REQUIRED=true` 并给 sessions REST 加鉴权，避免中断现有功能。
- [ ] **adapters 外部 webhook `/{id}/inbound` 鉴权单独设计**
  - `POST /api/v1/adapters/{adapter_id}/inbound` 是**外部 webhook 入站**端点，调用方为第三方系统而非已登录前端，**不适用 Bearer**。
  - 其鉴权方式需在 M4 **单独设计**：建议采用**签名校验 / 共享密钥**（如 HMAC 签名头 + 时间戳防重放），或置于 API 网关鉴权之后；与 sessions/adapters 其余管理类端点的 Bearer 鉴权区别对待。
  - 注意：决议②已在 cloud 模式下线整个 `/adapters/*` HTTP 路由（含 `/{id}/inbound`）；若 cloud 形态后续确需对外暴露 webhook，须在 M4 设计专门的鉴权与挂载策略后再放开。

## 4. 代码改动落点（决议②）

```python
def create_app() -> FastAPI:
    app = FastAPI(title=settings.APP_NAME, version=settings.APP_VERSION, lifespan=lifespan)
    app.add_middleware(CORSMiddleware, ...)

    is_cloud = settings.DEPLOYMENT_MODE == "cloud"

    # 始终挂载（local/cloud 共用）
    app.include_router(sessions_router, prefix="/api/v1")
    app.include_router(skill_forge_router, prefix="/api/v1")
    app.include_router(skill_store_router, prefix="/api/v1")
    app.include_router(auth_router, prefix="/api/v1")
    app.include_router(teams_router, prefix="/api/v1")
    app.include_router(projects_router, prefix="/api/v1")

    # cloud 下线 launcher / adapters HTTP 路由（决议②）
    if not is_cloud:
        app.include_router(adapters_router, prefix="/api/v1")
        app.include_router(launcher_router, prefix="/api/v1")

    app.include_router(ws_router)
    # root / health ...
    return app

app = create_app()
```

## 7. M3 评审决议（延续记录）

> 本节延续上文 ADR 序列，记录协调者对 **M3「本地代理」三项待拍板项**的最终决议。上游：`M3-本地代理实施记录.md` §10「评审决议与周知事项」、§2.2（D1）、§3.3（可写根白名单）、§4（hash 一致性），`M0-解耦设计与接口契约.md`（§4 端点、§5.3 可写根、§7 hash、§9 分歧 D1 / 风险 R3），`contracts/local-agent-api.md`（冻结契约 7 端点、`transfer` 字段）。
>
> 状态：**已决议**。三条结论**均不改动 M3 代码**（维持现状 / 冻结 7 端点），后续动作登记到 §8（M5 待办）与 §9（范围约束）。

### 决议⑤：白名单登记机制 = 采纳「browse 即登记」，"显式注册端点"并入 M5

对应 M3 §3.3 / §10、M0 §5.3。

- **结论**：采纳 M3 现状 **「browse 即登记」**——用户经 `GET /local/browse` 浏览/选定目录，即把 `current` 目录与其列出的子目录登记为可写根，`write-skill` 据此校验。以此**保持本地代理 7 端点冻结不变**（不新增契约外端点）。
- **延后项**：是否引入更显式的 **「显式注册端点」**（会突破 7 端点冻结）的评审，**并入 M5（桌面交互阶段）** 再定——届时结合桌面端「确认部署目录」交互一并设计；若维持 browse 登记则在 M5 明确收敛该议题。
- **性质**：**确认维持现状，无需改代码**。后续待办见 §8。

### 决议⑥：D1 资源传输 = M3 维持 inline，切 url 推迟到后期（M5 之后）

对应 M3 §2.2 / §10、M0 §9（分歧 D1）、契约 `transfer` 字段。

- **结论**：M3 **维持 `transfer:"inline"`（base64 内联）**，文本 utf8 / 二进制 base64 内联随产物下发并忠实落盘。
- **延后项**：大体积二进制资源切 `transfer:"url"`（需**云端对象存储** + 本地**带 Bearer 下载并校验 sha256 落盘**）**推迟到后期（M5 之后）**。契约已预留 `url` 字段（M3 对 `transfer=url` 显式返回 `BAD_REQUEST`），切换无需改契约签名。
- **性质**：**维持现状，无需改代码**。后续待办见 §8。

### 决议⑦：R3 文件名 Unicode / 跨平台 = 当前 Windows-first，macOS NFD 验证推后

对应 M3 §4.1(#7) / §4.2 / §10、M0 §7 / §9（风险 R3）。

- **结论**：当前 **Windows-first**。文件名 Unicode 统一**不做 NFC/NFD 归一**（与云端 `as_posix()` 口径一致，已实测 TS 与云端 Python 同一目录树 hex 位级相等）。
- **延后项**：**macOS NFD 文件名**两端（本地代理 TS `hash.ts` / 云端 Python `_compute_dir_hash`）hash 一致性**专项验证推后**，待将来覆盖 macOS 平台时再做。
- **性质**：**维持现状，无需改代码**。范围约束见 §9。

## 9. 范围约束

> 承 §7 决议⑦。明确当前阶段的平台范围与推后项。

- **当前 Windows-first**：hash / 文件名口径以 Windows 为准（开发实测 win32），文件名 Unicode 不做 NFC/NFD 归一。
- **macOS（NFD）跨平台 hash 一致性验证推后**：覆盖 macOS 平台时，再对 NFD 文件名两端（本地代理 TS `hash.ts` / 云端 Python `_compute_dir_hash`）一致性做专项验证；在此之前不承诺 macOS 文件名场景下的 dirty 判定一致性。
