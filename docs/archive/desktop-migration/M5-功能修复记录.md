## 1. 任务① 设备身份模型（服务端铸造 + 注册端点 + 桌面/前端过渡）

### 1.1 后端：`devices` 表 + `POST /devices/register`

**数据模型** `models/device.py`（严格按设计 §2.2 DDL）：

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| `id` | VARCHAR(36) PK | **服务端铸造** uuid4（= 规范 device_id） |
| `user_id` | VARCHAR(36) FK→users(CASCADE) idx | 归属用户 |
| `client_uuid` | VARCHAR(64) idx | 本机持久 uuid（幂等键，**非鉴权凭证**） |
| `platform/hostname/app_version/agent_version` | — | 展示/诊断元数据 |
| `status` | VARCHAR(16) | `active`/`revoked`（撤销不删行） |
| `last_seen_at` / `last_sync_at` / `revoked_at` | DateTime | 心跳 / 对账预留 / 撤销时间 |
| `created_at` / `updated_at` | DateTime server_default now() | — |
| **唯一约束** | `uq_device_user_client (user_id, client_uuid)` | 同机同用户幂等命中同一行；同机多账号各自独立 |

> `last_sync_at` 为「平台安装态对账」预留（与设计 DDL 对齐，避免 M5-b 再加列），本阶段不写入。

**注册端点** `POST /api/v1/devices/register`（`api/devices.py` + `services/device_service.py`）：
- **鉴权**：`Depends(get_current_user_id)`（Bearer）；缺/失效 token → 401。
- **入参**：`DeviceRegisterRequest`（见 §1.4 DTO）；**绝不接受 `device_id` 入参**——device_id 一律服务端铸造（防伪冒）。
- **幂等 upsert**：按 `(user_id, client_uuid)` 命中则刷新元数据 + 心跳并**重新激活**已撤销设备；未命中则 `INSERT` 铸造新 uuid4。
- **守 M2 决议④**：只铸造设备身份、**绝不签发配对令牌**（响应无任何 pairing 字段，已单测断言）。

附带实现（同属「设备身份这一层」，便于撤销/管理与越权测试，**非** platform_skill_installs）：
- `GET /api/v1/devices`：列举「我的」设备（仅本人）。
- `DELETE /api/v1/devices/{deviceId}`：软撤销（status=revoked，不删行）；**归属校验**——非本人设备 → 403，不存在 → 404。

**挂载**：`main.py` 在 local/cloud **两模式均挂载**（属云端数据端点、无本地盘依赖，设计 §7.3）。

### 1.2 Alembic 纯增量迁移

### 1.3 桌面壳：占位 uuid 升格 + 回写

`deviceId.ts` 收敛 M5-a 占位：
- `getOrCreateClientUuid()`：读/建本机 `clientUuid`；**平滑迁移**——旧文件只有 `deviceId` 字段时视为 `clientUuid`（零数据丢失）。
- `getRegisteredDeviceId()` / `persistRegisteredDeviceId(id)`：读/写 `vibebara-device.json.registeredDeviceId`。
- `getEffectiveDeviceId()` = `registeredDeviceId ?? clientUuid`（**注入优先级**）。

`index.ts` 装配：注入 `clientUuid` + 有效 `deviceId`；注册 `persistDeviceId` IPC 回调（落 registeredDeviceId + 热更 `runtimeConfig.deviceId`，后续 `sendSync` 即取新值）。`preload` 暴露 `persistDeviceId(id)`、`clientUuid`。

### 1.4 前端：登录后注册流程

`api/devices.ts` 的 `ensureDeviceRegistered()`：
- 桌面形态 + 有 `clientUuid` → `POST /devices/register {clientUuid, platform}` → 拿 `deviceId` → 经桥 `persistDeviceId(deviceId)` 回写本机 + `setDeviceId(deviceId)` 更新前端运行时缓存。
- **web 形态 / 无 clientUuid → 安全跳过**（返回 null，不报错、不影响登录）；任何失败仅告警不抛出。

`authStore.ts`：`doLogin` / `doRegister` 成功后、`init()` 恢复已登录会话后，均 `void ensureDeviceRegistered()`（幂等）。

### 设备注册端点 DTO（契约 §4.2.1，camelCase）

```ts
// 请求 POST /api/v1/devices/register  （Authorization: Bearer）
interface DeviceRegisterRequest {
  clientUuid: string;        // 必填；本机持久 uuid（幂等键，非凭证）
  platform?: string;         // win32|darwin|linux
  hostname?: string;
  appVersion?: string;       // 桌面壳版本
  agentVersion?: string;     // 本地代理版本
}
// 响应（success + 服务端铸造的设备身份；绝无配对令牌字段）
interface DeviceInfo {
  deviceId: string;          // 服务端铸造 uuid4（规范 device_id）
  clientUuid: string;
  platform: string;
  hostname?: string;
  appVersion?: string;
  agentVersion?: string;
  status: 'active' | 'revoked';
  lastSeenAt: string | null; // ISO-8601
  lastSyncAt: string | null;
  createdAt: string | null;
}
interface DeviceRegisterResponse { success: boolean; device?: DeviceInfo; error?: string }
// GET /api/v1/devices → { success, devices: DeviceInfo[] }
// DELETE /api/v1/devices/{deviceId} → { success, deviceId, status:'revoked' }（非本人 403 / 不存在 404）
```

### 安全论证（设计 §3.4 / §8）
- **device_id 非鉴权凭证**：任何带 device_id 的云端调用仍以 **Bearer 为身份**；撤销端点按 `device.user_id == current_user_id` 归属校验，越权 → 403。
- **防伪冒**：客户端不能声明任意 device_id（服务端按 Bearer 用户铸造）；`clientUuid` 仅幂等键，猜中也无法用（仍需 Bearer + 归属）。
- **多用户同机**：同 `clientUuid` 被两个账号登录 → 两行独立设备身份（`uq_device_user_client`），互不串扰。
- **守 M2 决议④**：注册端点不签发配对令牌；配对令牌仍由桌面主进程注入、云端不签发。

## 2. 任务② 本地代理端口漂移 → IPC 推送热更

### 2.1 桌面壳：分配新端口时 IPC 推送

`localAgentManager.ts`：
- 新增 `findPort?(preferred)` 与 `onPortChange?(port)` 选项（默认不漂移，兼容纯 node smoke）。
- **重启路径** `restartNow()`：spawn 前 `await findPort(currentPort)`——原端口仍空闲则复用，否则分到**新端口**；端口变化经 `setPort()` 通知 `onPortChange`。
- **以实际监听端口为权威**：解析子进程 stdout `监听 http://127.0.0.1:<port>`，覆盖 EADDRINUSE 顺延 / 漂移，`setPort` 热更并通知。

`index.ts` `onLocalAgentPortChange(port)`：热更 `runtimeConfig.localAgentBase/Port` + 经 `mainWindow.webContents.send(LOCAL_AGENT_CHANGED, {localAgentBase, localAgentPort})` 推送渲染层。`preload` 暴露 `onLocalAgentChange(cb)`（返回取消订阅函数）。

### 2.2 前端：`localAgentClient` baseURL 动态读取

`api/client.ts`：
- `localAgentClient` 创建时 `baseURL` 仅作初值；**请求拦截器每次 `config.baseURL = getLocalAgentBase()`**（动态读取 `runtimeConfig.localAgentBase`），端口漂移后即时生效。
- 模块加载时若桥存在 → `onLocalAgentChange((p) => updateLocalAgentBase(p.localAgentBase, p.localAgentPort))`（更新缓存）。**web 形态桥不存在 → 跳过，行为不变**。

`config.ts` 新增 `updateLocalAgentBase(base, port)`（热更缓存）/ `getLocalAgentBase()`。

## 3. 任务③ 白名单收紧（browse 即登记 → 确认选定才登记）

### 3.1 实现（保持 7 端点冻结）

- **`browse.ts`**：删除对 `current` 目录及其子目录的 `ctx.writableRoots.register(...)` 副作用 → browse 变为**纯只读浏览**（消除「看一眼就扩大白名单」）。
- **`writeSkill.ts`**（project scope）：授权来源改为**用户确认选定的 `deployPath` 根**——
  1. 校验 `deployPath` 为**已存在的真实目录**（不存在 → `WRITE_ROOT_FORBIDDEN`；是文件 → `NOT_A_DIRECTORY`）；
  2. `ctx.writableRoots.register(deployPath)` 登记为可写根（供本次及后续 hash/重部署/拉取复用）；
  3. 统一最终校验 `isAllowed(installPath)`：经 **realpath + `..` 逃逸防护**确保 installPath 严格落在已确认根内。
- platform scope 维持不变（落平台 skill 目录白名单，`createContext` 注入）。
- **未新增任何端点**——登记复用 write-skill 入参 `deployPath`，7 端点冻结不破。

### 3.2 前端配合

`FolderPicker.vue` 的「选择此文件夹」（`selectCurrent`）即「用户确认选定目标目录」的动作——选定路径随后作为部署/导入的 `deployPath` 传给 write-skill；`orchestration.ts` 在 `deployProjectSkillOrchestrated` 处标注 deploy_path 为授权来源。注释明确：浏览本身不再授权，写盘授权绑定确认选定的根。

### 3.3 新授权语义 & 安全论证

| 维度 | 旧（M3/M5-a） | 新（任务③） |
| --- | --- | --- |
| 授权来源 | browse 被动登记（current + 列出的所有子目录） | **用户确认选定的 deployPath 根**（write-skill 入参） |
| 白名单膨胀 | 浏览即扩大（看一眼就授权） | 仅「真正要写的、用户确认的根」入册 |
| browse 角色 | 读 + 写副作用（登记） | **纯只读** |
| 逃逸防护 | realpath + `..`（保留） | realpath + `..`（保留）+ deployPath 须为已存在真实目录 |
| 端点冻结 | 7 端点 | 7 端点（未新增） |

**安全论证**：
- 新模型**严格收紧**于现状——白名单不再因被动浏览累积，仅含用户在部署/导入流程**主动确认**的目标根；授权与「写意图」绑定，而非「浏览动作」。
- 配对令牌（路由层，仅本机渲染层持有）+ 仅监听 127.0.0.1 仍是「谁能调用」的第一道闸；realpath/`..` 逃逸防护确保即便 deployPath 被登记，实际写入也严格限制在 `{deployPath}/.{tool}/skills/{skillId}` 内，`skillId` 经校验无分隔符/`..`、`contents/resources` 经 `safeJoinUnder` 拦截 `..`。
- 残留信任假设：本地代理无法独立判定「用户已确认」，仍信任已配对渲染层的部署流程（与改前相同）。若要防御被攻陷的渲染层，可后续评估 M2 决议⑤ 的「显式确认可写根端点」（见 §6 残留点）。
